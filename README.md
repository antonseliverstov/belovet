# beloVET

Сайт ветеринарного врача-хирурга Владислава Белорыбца (Люберцы).

Боевой сайт https://belovet.ru работает на хостинге Timeweb (запущен 09.11.2026 без блога; формы заявок включены 12.11.2026). На GitHub Pages — прототип, закрыт от поисковиков.

## Боевой сайт belovet.ru (хостинг Timeweb)

`node tools/dist.js` собирает боевую версию в `dist/` во временной копии проекта, прототип на GitHub Pages не меняется. По умолчанию без блога и с формами (`BV_BLOG=1` включает блог, `BV_FORMS=0` выключает формы). В `dist/` только публичные файлы и `.htaccess` (https, без www, 404, кэш, сжатие). Содержимое `dist/` выкладывается в корень сайта на Timeweb: `~/belovet/public_html` (SSH vh466.timeweb.ru).

DNS belovet.ru остаётся на Timeweb (A-запись 92.53.96.136) — на GitHub Pages его не переключать: формы работают через PHP на хостинге, Pages PHP не выполняет.

Картинки в боевой сборке — WebP: `tools/webp.js` (вызывает `dist.js`) сжимает PNG/JPG из `assets/` и меняет ссылки в HTML; иконки и `og-image.jpg` остаются как есть, маски `*-mask` — без потерь; для крупных картинок главной (список `RESPONSIVE` в `webp.js`) — уменьшенные копии и `srcset` для телефонов. Ещё `dist.js` встраивает `fonts.css` прямо в `<head>` страниц. Исходники в `assets/` не меняются. Нужен модуль sharp: один раз `npm install` в корне проекта; без него — `BV_WEBP=0 node tools/dist.js`.

Сборку делать из клона с `core.autocrlf=false`: иначе на Windows файлы получат CRLF, изменятся метки версий `?v=` и у посетителей заново скачаются все стили и скрипты.

Режим запуска включает сам `dist.js` (`BV_LAUNCH=1`): адреса в canonical, Open Graph, разметке, sitemap и llms.txt — https://belovet.ru/, без `noindex`, `robots.txt` открыт для поисковиков и ИИ-ассистентов, без полосы «Прототип». Настройки в начале `tools/build.js`:

- `METRIKA_ID` — номер счётчика Яндекс Метрики (только на боевом сайте);
- `VERIFY` — коды подтверждения Яндекс Вебмастера и Google Search Console, если подтверждать не через DNS;
- `LEAD_URL` — адрес обработчика форм (см. ниже);
- `OPERATOR` — данные оператора персональных данных для `privacy.html` и `consent.html`.

Осталось до полного запуска:

1. Медицинская вычитка статей врачом (до включения блога).
2. При переходе на отправку заявок в Telegram или облачную CRM — снова к юристу: трансграничная передача, уведомление Роскомнадзора.

Сделано: формы заявок → письмо на vladislav@belovet.ru (12.11.2026; юрист одобрил политику и согласие, проверено тестовыми заявками).

### Проверка целостности файлов (tools/integrity.php)

Раз в сутки сверяет все файлы сайта на хостинге с эталоном (хеши после последней выкладки) и пишет разработчику, если что-то изменено, добавлено или пропало — особенно `api/lead.php`: подменённый обработчик может тихо копировать заявки. По понедельникам — короткое «всё в порядке». На хостинге: `~/belovet/private/integrity.php`, адрес для писем — `~/belovet/private/integrity.conf` (`alert_to=...`, в репозиторий не кладётся).

**После каждой выкладки:** `ssh belovet 'php ~/belovet/private/integrity.php --update'` — иначе придёт тревога о вашей же выкладке. Если менялся сам `tools/integrity.php` — сначала скопировать его на хостинг.

Cron (панель Timeweb → Cron, раз в сутки): `/usr/bin/php ~/belovet/private/integrity.php `

Ограничение: при краже пароля хостинга злоумышленник может обновить и эталон — от этого защищают пароль и двухфакторная аутентификация Timeweb.

### Обработчик форм (functions/lead.php)

Заявки с трёх форм (запись, экстренно, вопрос врачу) уходят письмом на vladislav@belovet.ru через PHP-скрипт на том же хостинге Timeweb: данные остаются в России, Telegram и облачные сервисы не используются (решение 10.11.2026; позже — CRM). Пароли не нужны: письмо отправляет mail() хостинга от site@belovet.ru.

Включено по умолчанию: `node tools/dist.js` кладёт скрипт в dist/api/lead.php, формы отправляют на /api/lead.php. Журнал согласий — `~/belovet/private/consents.jsonl` (вне папки сайта). После изменений обработчика — тестовая заявка (имя с «ТЕСТ»), проверить письмо и удалить тестовую строку из журнала согласий.

Старый вариант для Yandex Cloud Functions (functions/lead/) не используется.

### Журнал вопросов — идеи для статей

Блок «Вопрос врачу» на шаге с описанием сохраняет вопрос в `~/belovet/private/questions.jsonl` на хостинге: дата, кошка/собака, «Срочно», текст (имя, телефоны и почта вычищаются), какие статьи предложил сайт и насколько подошли. Имён и телефонов в журнале нет; вопросы, отправленные врачу, помечаются строкой `{"q": …, "sent": true}`. Хранится год (политика, раздел 5).

Раз в месяц: забрать файл по SFTP одним подключением и запустить `node tools/questions-report.js questions.jsonl ГГГГ-ММ` → `brand/questions/ГГГГ-ММ.md`: частые темы, вопросы без подходящей статьи (кандидаты в новые статьи), статьи, которые сайт предлагает чаще всего.

В Метрике при подключённом счётчике срабатывают цели `lead_book` (запись), `lead_question` (вопрос врачу отправлен), `ask_name` и `ask_articles` (шаги блока «Вопрос врачу») и `phone` (клик по номеру) — их нужно создать в настройках счётчика как JavaScript-события. В настройках Вебвизора отключить запись содержимого полей.

После запуска: добавить сайт в Яндекс Вебмастер и Google Search Console, отправить sitemap.xml, указать регион (Люберцы) в Вебмастере, проверить карточку в Яндекс Бизнесе.

## Структура

- `index.html` — главная страница
- `assets/` — логотипы и фото для сайта (уменьшенные)
- `brand/` — цвета бренда (`colors.css`) и исходники логотипа
- `materials/` — прайс и исходные фото, только локально, в репозиторий не попадает

## Операции и цены

- Все операции, цены, поисковые фразы и тексты страниц — в `data/procedures.js`.
- После правки запустить `node tools/build.js`: он пересоберёт страницы `operations/*.html`, данные поиска `assets/search-data.js`, список категорий на главной (между метками `SURGERY:START/END`) и `sitemap.xml`.
- Страницы и блок на главной вручную не править — изменения сотрёт следующая сборка.

## Формы

Формы записи пока не отправляют заявки (статичный сайт). Обработчик — в конце `index.html`, место отмечено комментарием.
